Nuke Comp Progress Reporter — Overview

This workflow auto-generates shot progress reports from Nuke comps and posts them to ShotGrid (Flow Production Tracking), built as a Griptape Nodes workflow published as a Nuke gizmo. When an artist runs it, a Python node reads the comp's .nk file as plain text and builds a compact, structured digest of the shot — pulling the shot code and format from the Root node's path, the working frame range, the plate Reads, the Write/output status, a histogram of node operations (merges, grades, keyers, etc.), and counts of total versus disabled nodes — deliberately skipping the huge serialized blobs (roto, tracker data) so the summary stays small and signal-rich. That digest is handed to an Agent node running Claude (via an Anthropic Prompt config), which writes a concise progress note describing the comp's current state and what looks unfinished. The artist reviews and edits the generated text before anything is sent, then the note is published to ShotGrid — ideally as a dedicated Progress Report entity linked to the shot's comp Task, with the deterministic fields (version, node count, output status) stored alongside the prose so reports become queryable, trendable data rather than buried chat-stream notes. The digest parser is pure Python with no external dependencies, so it behaves identically in the Griptape Nodes editor and in a published bundle on any machine.
